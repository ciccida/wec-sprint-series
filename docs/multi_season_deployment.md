# 本番環境実装用：AIへの指示ガイド

このドキュメントは、ローカル環境で完成させた「マルチシーズン対応システム」を、本番のリポジトリに正確に移し替えるための指示書です。

## 🎯 依頼の全体像
「WEC Sprint Series サイトを、将来のシーズン追加に対応したマルチシーズン・アーカイブ形式へアップグレードしてください。既存の Vol.2 実績を維持しつつ、Season 3 以降を動的に追加できる柔軟な設計を導入します。」

---

## 🛠 ステップ別の具体的な指示

### ステップ1：データ構造の階層化 (Data Migration)
以下の3つのデータファイルを、従来のフラットな配列から `{ "Vol2": [...], "Vol3": [...] }` という階層構造に書き換えてください。
- `src/data/ranking.js`
- `src/data/raceResults.js`
- `src/data/timeAttackData.js` (Season 3 / Vol3 から正式開始)

> **重要**: 既存の Vol.2 のデータはすべて `"Vol2": { ... }` の中に格納し、消さないようにしてください。

### ステップ2：コンポーネントの汎用化 (`Ranking.jsx`)
`Ranking.jsx` を、外部からデータ（props）を受け取って描画する動的コンポーネントに改修してください。
- `selector` プロパティを追加し、赤いロゴ見出し（`h2`）のすぐ下に配置できるようにします。
- データのソートやランキング計算は、渡された `data` プロパティに対して行うように修正してください。

### ステップ3：統合リザルトページの刷新 (`Results.jsx`)
`Results.jsx` を以下の仕様で再構築してください。
- **独立したステート管理**: タイムアタック、ランキング、レース結果の3セクションが、それぞれ個別にシーズンとラウンドを選択できるようにします。
- **インテリジェントな初期表示**: 
    - 読み込み時に、各シーズンの最新ラウンド（データがある最後の方）を自動で選択するように `getLatestRound` ロジックを実装してください。
    - タイムアタックにデータがない場合は Rd.1 をデフォルトにします。
- **動的なラベル変換**:
    - ボタンの表示に命名規則を適用します（`Vol2` → `Vol.2`、`Vol3` 以降 → `Season 3`）。

### ステップ4：トップページの自動化 (`Home.jsx`)
トップページが常に「最新かつ有効なデータ」を出すようにロジックを更新してください。
- 全シーズンから「データが存在する最新のシーズン」を逆引きで探し出し、自動でその情報をプレビュー表示させます。
- タイムアタックのプレビュー件数を上位3名（limit=3）に制限し、見出しを `PROVISIONAL TOP 3` に変更してください。

---

## ⚠️ 実装時の注意点 (AIへの念押し)
- **インポートの欠落に注意**: `Home.jsx` で `Ranking`, `TimeAttackResults`, `Link` などのインポートが消えないようにしてください。
- **構文エラーの防止**: 特に `raceResults.js` のような巨大なオブジェクトを扱う際、閉じ括弧（`]`, `}`）の整合性を厳密に守ってください。
- **命名規則の厳守**: `Vol.2` までは「Vol.」表記、それ以降（Vol.3〜）は「Season 3」表記とすることを徹底してください。
